# CLAUDE.md

A local web page (FastAPI + vanilla JS) for three skills kept in `skills/`: `view-concept` (an explanation in six phases), `view-branch` (a branch review) and `view-refactor` (a triage of existing code). Each skill is self-contained: it carries every rule it follows and never sends the agent to read another skill, so a rule shared by two skills is written in both. A session records its workflow, the skill driving it, in `plan.json`; the workflow picks the verdict set the page shows, one list per workflow in `verdicts.yaml`, where each verdict carries the `tone` the page colours it with. The skills (`skills/<name>/SKILL.md`, written for any agent: Claude Code, Codex, Jazz) write session files. The page renders them and sends comment batches back through an inbox file, which `view-concept watch` (under a background monitor) or `view-concept wait` (blocking, one batch per call) hands to the agent session. Usage is in the README; commands, session files and page controls are in `docs/reference.md`.

- The file contract (`plan.json`, `sections/` (`<id>.md`, or `<id>.html` for an HTML section, with its media folder `<id>/`), `audit.json` (which `view-concept check` also writes, issues `forward` and `early`; its section problems are only printed), comment batch format, `questions.json` (status `open`, `answered`, `skipped` or `deferred`, the optional `recommended` answer, `background` and anchor `section`, the `unclear` notes of a deferred question, an answer's `from: "terminal"` when `view-concept answered` closed it without a batch, `view-concept anchor` and `reask`), the `awaiting-answer` phase of an agent question (not set during the `scoping` phase, which a question leaves alone), the `answer` action of the batch that answers or skips it (a skip's entry is `{question, skipped: true}`, an « I don't understand »'s `{question, unclear: true, note}`), and the `plan` (ends scoping, marking open questions skipped), `grill` and `stop-grill` actions) is shared with the skills, `skills/view-concept/SKILL.md`, `skills/view-refactor/SKILL.md` and, for what a branch review adds (`"part": "refactoring"`, the applied changes section `applied`, the item fields under `item` (with the optional `batch`), `"kind": "finding"`, the `awaiting-model`/`awaiting-pr` phases, the `approve-model`/`create-pr` actions, `change-history.json` (`view-concept change`), `terminal-messages.json` (`view-concept message`), `implemented.json` (`view-concept implemented`: the last model change an implementer took into account; the changes logged after it are not implemented yet), the `rewrite` flag of a `plan` batch, `plan.json`'s `initial_request` and `base`, and the context its agents start from (`view-concept context`, `context.py`)), `skills/view-branch/SKILL.md` and its role files in `skills/view-branch/roles/`; `verdicts.yaml` and the session workflow are shared with `skills/view-branch/SKILL.md` and `skills/view-refactor/SKILL.md`. Change them together. `agent.json`, `threads/` (`threads.py`), `watch.json` (the watch's heartbeat, which the page shows as « Agent listening »), `seen.json` (the highlight baseline: each section's text at the last batch or « mark read ») and `published.json` (the publish record: link, time, fingerprint) belong to this repo alone (`agents.py` holds what differs between agents); the skills only see the thread line of a batch comment.
- `static/reader.js` (the published page's script) mirrors functions of `static/app.js` (term underlining, maths, Mermaid, the tooltip): change them together.
- Styling uses the omarchy-terminal-skin tokens only (`themes.css` and `terminal.css` are copies from the skill; don't edit them here).
- Lint, format and type-check must pass: `uv run ruff check --fix . && uv run ruff format . && uv run ty check .`, then `uv run pytest`.
- Never add AI attribution to commits or PRs.
